# 数据恢复与来源说明（T05-dsh-3）

## 一、结论摘要

- **实际采用来源：`backup.csv`（备用文件，全部记录）。**
- **主输入 `primary.json`：不可用**（不是合法 JSON），按 readme 规定直接改用备用文件，未做任何修复或改写。
- **数据记录数：2 条**
- **总件数（units 列求和）：8**

## 二、主输入可用性判断

判断依据仅来自 `primary.json` 自身内容，未做任何修补。该文件原始全文为：

```
{"items":[{"item_id":"b01","units":3},{"item_id":"b02","units":}]}
```

- 第 2 个对象的 `"units"` 键名之后直接是 `}`，缺少该键的值（JSON 语法要求冒号后必须有合法值）。
- 用标准 JSON 解析器（PowerShell `ConvertFrom-Json`）对该文件原文解析，结果为失败，报错：`无效的 JSON 基元: 。`
- 因此该文件**不是合法 JSON**，无法提取 `items` 数组。

结论：主输入不可用，触发 readme 中的降级规则——使用 `backup.csv` 的全部记录。

## 三、按 readme 规则的处理过程

readme 规定的读取顺序：

1. 先检查 `primary.json` 是否为合法 JSON；
2. 若合法，读取 `items` 数组；
3. 若不合法，使用 `backup.csv` 全部记录；
4. 不修复主文件、不混合两个来源；
5. 输出按 `item_id` 升序，统计 `units` 合计；
6. 报告如实说明来源与主文件可用性。

执行对应情况：

| 步骤 | 执行结果 |
| --- | --- |
| 合法性检查 | 失败（缺少 `units` 值），见第二节 |
| 走的路径 | 备用文件 `backup.csv` |
| 来源混合 | 无。`primary.json` 中虽能读出 `b01:3`，但按"不混合两个来源"的要求**未采用**该值 |
| 修复输入 | 无。两个输入文件均只读访问，未修改、未重写 |
| 排序 | 已按 `item_id` 升序（`b01` < `b02`） |

## 四、`backup.csv` 实际内容

原始文件逐行内容：

```
item_id,units
b01,3
b02,5
```

- 表头：`item_id,units`，与目标输出列顺序一致。
- 数据行 2 行，无空行、无重复 `item_id`、无缺失值。
- `units` 两列均为正整数。

## 五、输出与统计

`items.csv`（列顺序 `item_id,units`，按 `item_id` 升序）：

| item_id | units |
| --- | --- |
| b01 | 3 |
| b02 | 5 |
| **合计** | **8** |

- **数据记录数：2**
- **总件数（`units` 求和）：3 + 5 = 8**

- 交付物为两个文件：`items.csv`、`recovery.md`。
