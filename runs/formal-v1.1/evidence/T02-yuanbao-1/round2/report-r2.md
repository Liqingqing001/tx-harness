# 区域订单核对报告（第二轮：仅华东）

## 核心结论
- 采用政策：**v2（替代v1）**；政策冲突以版本号较新的v2为准。
- 第二轮变更范围：**仅将汇总范围收窄为 `region = 华东`**。去重、paid筛选、数字合法性、退款倒挂校验、净金额公式、十进制计算、两位小数及首个原因归因规则均沿用第一轮，不改动。
- 新增原因代码：**`out_of_scope`**，但只在订单原本能够通过政策v2条款1—4、只是区域不属于华东时使用。
- 有效订单数：**2 单**；净金额合计：**130.50 元**。
- 排除记录：**5 条**，全部列入 `exceptions-r2.csv`。
- 第一轮文件 `summary.csv`、`exceptions.csv`、`report.md` 原样保留，未覆盖。

## 变更范围与判定顺序
第二轮不是“先按华东过滤、再跑政策v2”，而是：

1. 先执行政策v2**条款1**：同 `order_id` 保留最大revision；
2. 再依次执行**条款2→3→4**：not_paid → invalid_number → refund_exceeds_amount；
3. 对通过前四项校验的记录，最后执行第二轮新增的范围校验：非华东记 `out_of_scope`；
4. 只对最终华东有效记录按**条款5**计算 `amount-refund` 并汇总。

这个顺序保证新增的 `out_of_scope` 不会掩盖原有数据质量问题。例如 o4 虽在华南，但先命中条款3，仍记 `invalid_number`，**不记** `out_of_scope`；每条排除记录只写第一个适用原因。

### 逐条说明
- **o6（rev.1）**：政策v2条款1先于区域范围判断。保留o6 rev.2后，rev.1排除；即使rev.2属华南，也不能把旧版改标成 `out_of_scope`。
- **o3**：位于华东，但cancelled命中条款2，因此不是范围外问题。
- **o4**：金额`abc`使十进制净额无法计算，命中条款3；区域不是其首个失败原因。
- **o7**：退款超过原额，命中条款4；不能按`-20.00`冲减华东净额。
- **o2**：这是唯一使用新代码的记录。它原本是第一轮有效订单，第二轮仅因华南而移出汇总；`out_of_scope` 表示“数据有效、不在本次报告范围”，不等同于数据错误。

### 变化归因
- **金额减少320.00元 = 华南移出范围的两单**：
  - o2：`200 - 0 = 200.00`；
  - o6有效版本rev.2：`130 - 10 = 120.00`。
- **有效订单减少2单**：正是o2与o6的代表版本rev.2，合计减少 `200.00 + 120.00 = 320.00` 元。o2原本完全有效，故新增 `out_of_scope`；o6在条款1去重阶段已有旧版rev.1命中 `duplicate_older_revision`，按“只写第一个适用原因”沿用该代码，不为同一order_id重复追加一行。
- **华东自身结果完全不变**：o1、o5仍有效，o3、o7仍因各自质量规则排除。因此差异100%来自范围收窄，**没有任何金额差异来自改了去重、paid、数字、退款或净额规则**。

> 口径说明：`exceptions-r2.csv` 的5行对应输入中的5条物理记录，其中o6特指被条款1排除的rev.1；业务订单层面，第二轮未进入华东汇总的是o2、o3、o4、o6、o7共5个order_id。o6的代表版本rev.2属于范围外，但其order_id已因旧版去重原因在异常表中出现，依照附件“不追加revision后缀、每条只记首个原因”的规则不重复输出。该展示口径只影响异常清单行数，不影响2单有效、130.50元的汇总结论。
