## 3. 主输入不可用的判断依据

`primary.json` 共 67 字节，单行内容为：

```json
{"items":[{"item_id":"b01","units":3},{"item_id":"b02","units":}]}
```

- 第二个对象的 `units` 键后**缺少值**，直接在 `}` 前结束，属于残缺的 JSON 基元（值为空）。
- 使用标准 JSON 解析器（PowerShell `ConvertFrom-Json`）实际解析该文件，返回错误：`无效的 JSON 基元: 。`（即遇到空的 JSON primitive）。
- 因此该文件不满足 RFC 8259 的合法性要求，属于**语法层面的非法 JSON**，而非"合法但字段为空"的情况。`items` 数组虽在文本上可见，但整体文档无法被解析，不能作为可信数据源，故不读取其 `units`（其中一条本就不存在）。

> 说明：如果 `units` 写作 `null`，文档仍合法，按规则应走主输入；但本例是值完全缺失，文档非法，因此必须走备用文件。这是本次判定与"字段为空"场景的关键区别。
