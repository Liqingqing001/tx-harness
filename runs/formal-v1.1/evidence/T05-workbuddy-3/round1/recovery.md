# 数据恢复报告

## 结论摘要

- **实际采用的来源**：备用文件 `backup.csv`
- **主输入是否可用**：不可用（非法 JSON）
- **数据记录数**：2 条
- **总件数（units 列求和）**：8

## 读取规则与执行过程

依据 `readme.txt` 的规定：

1. 先检查 `primary.json` 是否为合法 JSON；若合法则读取其 `items` 数组；若不合法则使用 `backup.csv` 的全部记录。
2. 不修复主文件，不混合两个来源。
3. 输出按 `item_id` 升序排列，并统计 `units` 合计。
4. 报告如实说明来源与主文件可用性。

## 主输入可用性判断

对 `primary.json` 执行标准 JSON 解析，结果失败：

- 报错：`JSONDecodeError: Expecting value: line 1 column 64 (char 63)`
- 具体位置：第二个元素的 `"units":` 之后直接出现 `}`，即 `"units":}` —— 冒号后缺少合法的值（既非数字，也非字符串/null/布尔/数组/对象）。
- 因此判定 `primary.json` **不是合法 JSON，不可用**。

按要求**未对主文件做任何修复或改写**，也未从其中提取任何数据（不混合来源）。

## 采用来源与数据

由于主输入不可用，按 readme 说明改用备用文件 `backup.csv` 的全部记录。未编造任何缺失数据。

| item_id | units |
| --- | --- |
| b01 | 3 |
| b02 | 5 |

- 记录已按 `item_id` 升序排列（`b01` → `b02`），原本即为升序。
- 数据记录数：**2**
- 总件数：`3 + 5 =` **8**
