# 评测协议 v0.2（待试跑校准，正式运行前冻结）

## 1. 研究问题
Harness 是围绕模型执行任务的环境：文件与工具接入、权限、状态维护、调度、恢复、产物交付和过程记录。评测分两条线：
- 五产品原生体验：同任务同输入同完成条件，比较产品组合效果，不能称为纯 Harness 因果排名。
- 受控归因：仅对可验证匹配条件的子集实施一次只改变一个因素的实验。不匹配模型版本、推理预算、Skill 或权限时保留混杂。

相同模型名称不保证后端与系统提示相同。无法取得这些信息须记 unknown。原生产品结果、过程行为和根因结论分别报告。

## 2. 任务资产与分层
每个任务必须有固定输入、提示、完成条件、期望环境状态、二元 Rubric、证据要求和版本。T01 是环境检查；T02 是主用例；T03 尚未完成，不计分。
端到端检查结果是否达标；过程检查可观察动作是否符合约束。不规定唯一工具调用顺序，不因采用不同但正确的方法扣分。
黄金参考产物用于校准评分，不等于唯一合法答案。必过项标示任务成功底线；错题集收录真实失败；挑战集标示已冻结的能力边界。不得将自造失败冒充产品现场。

## 3. 实验控制
五款分别记录产品版本/入口/套餐/指定模式/模型与推理档位/自定义与内置Skill/工具权限/时间时区/输入SHA256/协议提交SHA。
主轨不加载个人自定义Skill；关闭记忆与历史影响（可关闭时），使用独立新会话和独立输入副本；记录无法关闭的因素。只提供任务明确允许的文件，不暴露答案或评测代码。
试跑：各产品一次，不计正式成绩。试跑结束统一冻结时限（初始候选每轮20分钟）、统一提示、评分及运行顺序。正式每产品三次完整两轮试验，保存实际交错顺序与时间；禁止挑最好结果。
第二轮在同一会话发送，使用第一轮状态，即使第一轮失败也尝试第二轮并标注前置失败；不能重置成一次独立试验。单轮超时即止，保留部分产物。收到明确完成声明或达到预算时结束该轮。
合理权限确认可执行并记录，不算人工代做；除预设答复不额外提示答案。若人工纠正使任务完成，另记 assisted，不计无辅助成功。
产品不支持约定输入/输出：确认后按该任务失败记录，原因记能力范围。网络/采集设施故障单列无效运行并补跑，保留所有记录；产品自身超时/崩溃不排除。规则在正式开始前固定，不按结果择优排除。

## 4. 二元判定与缺失
每条为 pass / fail / unknown / not_applicable（NA）。pass=证据满足断言；fail=有效运行中证据明确不满足。产物缺失是端到端 fail；内部过程不可见是 unknown，不冒充 fail。NA 必须是事前适用条件不成立并写理由，不能用来排除差表现。
评测者采集失败不能扣产品分，该运行无效；产品不提供日志则保留运行，过程项 unknown。现象与原因置信度独立填写。

## 5. 汇总与门槛
端到端每轮结果分：100 × 已通过E项数 / 适用E项总数（unknown留在分母，标记分数为已验证下界，并报告未决数）。T02 E项等权，任何必过项失败则任务不成功，其他加分不能抵消。
一次完整试验无辅助成功：两轮所有适用必过项均通过且无额外人工纠正；存在未知必过项则标未决，不记成功。
主表列：完整任务成功数/有效试验数、每轮结果分、单项通过情况、失败/未决数、时间中位数及范围、人工介入次数。T02 仅一个任务族，不能推广为通用能力排行。
过程项单独列 pass/fail/unknown；过程可观测率=(pass+fail)/适用P项数。过程通过率=pass/(pass+fail)，必须同时给分母；不能把低可见性的高通过率当优胜。产品是否提供可用日志是独立能力描述，不与任务结果加权混分。
取消v0.1的40/20/15/15/10主总分。未来多任务等权汇总前冻结任务集合和规则，覆盖不一致不排名；现阶段只比较同任务结果。三次试验仅探索性描述，不作显著性声明。

## 6. 校准与回归
正式前对同一批试跑产物进行第二评审者独立评分；无人协助时本人隔时打乱产品标签复评，并注明非独立双评。报告逐项一致数/双方已判定项数，保存分歧与裁决；未解决的关键分歧须改规则再试跑。
正式阶段如发现规则误判：保留旧分，发布新Rubric版本，对所有产品可用原证据统一重评，证据不足统一补跑；不能只修一款成绩。
每周将真实Bad Case归入case pool，分流为产品问题、评测缺陷、外部故障或未知；新增错题任务使用新版本，不追溯混入旧分母。产品版本变化时重跑固定回归集。

## 7. 归因实验
遵循 docs/case-review.md。先定位最早可确认的偏差，再检查上游是否已提供正确输入。模型、Skill、Harness、外部依赖、评测错误、混合/未知均为合法结论。
Skill消融仅在能确认加载且可控时做同条件有/无配对实验。把SOP贴到聊天仅是提示干预，不等价于原生Skill。高置信原因需直接证据、重复或干预对照及主要替代解释检查；只有相关性最多作为候选原因。
