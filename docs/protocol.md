# 评测协议 v0.1（正式运行前冻结）

## 研究问题与边界
Harness 指围绕模型的执行环境：输入和文件处理、工具调度、状态维护、失败恢复、权限控制、产物交付和过程可追溯性。模型的推理、写作、事实知识能力不直接等同于 Harness 能力。

主报告分两条线，禁止混成因果排名：
- 原生产品体验：同任务、同输入、同完成条件，使用各产品默认可用能力，反映整个产品组合的表现。模型和内置 Skill 不可控时不能称为纯 Harness 排名。
- 受控归因：仅在能够验证相同模型版本、参数、工具权限和 Skill 内容的产品子集中对照；无法匹配的产品只做过程观察，不宣称排除了模型影响。

即使模型名称相同，隐藏提示、后端版本和推理预算仍可能不同，需列出残余混杂。不能为凑齐五款比较而假设这些条件一致。

## 运行控制
记录日期时区、客户端版本或网页 URL、套餐、模型名称（不可见写未知）、模式、Skill 名称/版本、工具权限、系统环境和费用可见性。每次新会话，同一输入字节、同一提示、同一超时预算（试跑后统一确定，建议 20 分钟）。保留失败与超时，不选择性重跑。网络故障单独标记，补跑须保留原记录。

每任务每产品重复三次；交错产品顺序；同一运行者；开始到最终产物可下载停止计时。需要追问时只用预设答案，额外人工操作逐项记录。工具自带等待也计入耗时。工具调用数仅作描述，不因调用多而扣分。

## Skill 消融
能关闭自定义 Skill 时先跑无自定义 Skill 基线，再增加同一公开 SOP（文字内容一致）做配对实验。将 SOP 放入聊天只代表提示干预，不能等价视为原生 Skill 加载。无法关闭的内置 Skill 标记未知/不可控。只有支持相同条件的子集才计算 Skill 增益。

## 归因规则
每项事件记录：现象、证据位置、候选原因、反证/替代解释、可复现实验、归因与置信度。
- Harness：可观察到上传截断、文件未持久化、调用路由/参数传递错误、权限处理失败等，并经独立检查或匹配条件复现支持。
- Skill：证明该 Skill 实际加载，且替换/移除后的配对结果支持差异；不能仅凭 Skill 存在就归责。
- 模型：须有输入输出及匹配执行环境的对照支持；仅答案错误不足以归责模型。
- 外部依赖：工具服务、网络或源文件错误有直接证据。
- 混合/未知：证据不能区分以上解释时必须保留。

置信度：高=直接日志/产物证据及受控复现，主要替代解释已检查；中=直接证据但有未排除混杂；低=仅界面现象或单次结果。现象置信度与原因置信度分开填写。三次重复只能说明有限样本稳定性，不能夸大统计显著性。

## 评分：每项 0/1/2 分
完成度40%：0=无可用产物或多数关键断言失败；1=部分关键断言通过；2=全部通过。
文件交付20%：0=文件缺失/损坏；1=可打开但格式或命名不符；2=文件齐全、可打开且规范符合。
异常处理15%：0=静默丢弃或误处理；1=发现但未正确隔离/解释；2=识别、正确处理并留痕。
人工负担15%：0=需人工代做关键步骤或未完成；1=需额外纠正/操作才完成；2=仅预设输入即完成。必要的合理权限确认不视为纠正，但单独记录。
过程可复核10%：0=无法定位结果依据；1=有部分引用/记录；2=关键结果能定位输入和操作依据。评测者录屏缺失是数据质量问题，不能扣产品分。

总分=各项分值/2×权重之和。每项附证据、理由、置信度；完成度是产品结果而非 Harness 因果指标。未测试写 NA，不当作零；确认任务在产品范围内但不支持的能力可记零并明确原因。只有相同任务覆盖才能比较总分。报告同时展示各次原始分、均值、范围、成功次数/总次数、耗时中位数，不只报综合榜。

评分先冻结；可请第二人盲评部分样本并保留分歧。主报告将各权重上下调整 20% 后重新归一化，检查名次是否变化；若变化则说明排名依赖权重。
